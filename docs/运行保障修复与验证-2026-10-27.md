**部署约定**

API 和 Worker 需一同升级并使用同一份环境文件。新增 SQLite 健康表自动创建，保留
原任务和业务数据。`/readyz` 仅提交一条固定大小的健康记录，不创建已丢失的数据库；
不访问 Keycloak 或防火墙。就绪失败返回 503，原任务受理与查询语义保持不变。

默认心跳周期 2 秒，阶段变化可提前更新；15 秒作为心跳过期时间及阶段结束宽限，
必须大于两倍周期。轮询、准备阶段默认 60 秒，配置与验证使用已有执行预算；等待
编排锁按任务/查询最长预算判断，连续等待不会重置该预算。

每个 API 进程最多运行一个全节点查询，设备内部仍按原配置并行；默认另允许 16 个
同类等待者，最多等待 10 秒。异类或容量超限返回 `503`、`Retry-After: 1`。完成结果
不缓存；跨 API 进程仍由原文件锁协调。配置见
[trade-access.env.example](../config/production/trade-access.env.example)。

审计目录：

```text
<runner>/<code>/job_artifacts/<job_id>/<run_id>/   # 配置、预检、验证，长期保留
<runner>/<code>/snapshot_artifacts/<run_id>/       # 普通查询，最近 20 次
<runner>/<code>/artifacts/<run_id>/                # 兼容读取的旧路径
```

事件响应新增 `audit_status`、`audit_warnings` 及逐事件 `run_id`，原 `events` 字段
保持。日志过期/删除或损坏时明确提示，旧版本已删除的文件无法恢复。任务审计目前
不自动过期；自动归档、容量上限和临时目录回收属于后续 P2-17 范围。
