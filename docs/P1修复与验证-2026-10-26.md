| 问题 | 修复后的行为 |
| --- | --- |
| P1-01 提交或保存失败被配置查询覆盖 | runner 必须成功，配置查询匹配不再覆盖失败；worker 每次执行均补做配置所启用的提交/保存，空增量计划也不跳过；save 要求明确成功信息 |
| P1-02 有效清单隐藏撤销残留 | state 查询增加原始地址、应用和组成员；逐虚拟系统检查地址，撤销不允许应用或组成员残留；缺少原始字段时拒绝判成功 |
| P1-03 增量重放不能恢复完整期望 | worker 将固定完整期望端口传给 Role，重新计算增删差量；恢复丢失的应保留端口，并处理空应用及悬空组成员 |
| P1-04 按名称删除错绑应用 | 完整 deny 先查询全部对象详情；检查实际 IP/掩码与详情完整性，通过后才开始删除；空应用中的错误 IP 也会被识别 |

IP 接口仍只改变地址成员，不替用户修复端口漂移。未知 IP 的部分地址残留、未入组应用
和错误 IP 绑定不会被静默采纳为基线。已有账本中的完整期望仍作为端口任务的恢复依据。
累计尝试上限保持不变；最后一次运行中断且未记录成功时，保守判失败，不凭配置存在
宣告成功。三台设备仍采用并行执行、有限重试和人工处理边界，不保证跨设备原子事务。
