| 审查项 | 本轮实现 |
| --- | --- |

| P2-13：重复请求重新执行 | 按用户与 `client_request_id` 在事务内受理，相同内容返回原任务，不同内容返回 409；兼容旧审计字段及重复历史数据；已成功、失败和取消任务均不重新入队 |

**执行与接口约定**

默认父任务预算 1800 秒、单次配置 Runner 900 秒、查询 300 秒、锁等待 10 秒。
API 与 worker 使用同一环境文件，示例见
[trade-access.env.example](../config/production/trade-access.env.example)。
任务详情新增 `deadline_at`、`precheck_attempt_count`；已有数据库在初始化事务中
补列和索引。旧任务在下次认领时获得一次执行预算，此后保持原截止时间。

取消入口：

```http
POST /api/v1/trade-access/jobs/{job_id}/cancel
POST /api/v1/admin/trade-access/jobs/{job_id}/cancel
```

普通入口校验所有者；管理员入口要求管理员角色及 `firewall.job.audit` 权限。
开始配置准备后返回 409。取消与准备配置之间通过数据库原子迁移竞争，晚返回的预检
不能恢复已取消任务，也不能写账本或设备。正在进行的只读预检仍会运行到完成或查询
超时，期间持有原编排锁。重新发起失败或取消的变更须使用新的 `client_request_id`。
完整约定见[接口设计与维护说明](接口设计与维护说明.md)。
